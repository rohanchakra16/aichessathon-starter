- Title: Single-repetition draw detection inside the search tree
- Family: search-draw-semantics
- Hypothesis: The champion's _forced_draw scores a repetition as a draw only at the on-board third occurrence (board.is_repetition(3)); inside the search tree the engine therefore walks into repetition lines and only recognises them one full cycle too late to steer away, which is the direct cause of the ~28/64 non-forced repetition draws from equal-or-better positions. Recognising the FIRST in-tree recurrence of a position as a draw (score 0.0) will give alpha-beta a correctly-timed reason to reject a repeating move whenever any non-repeating alternative evaluates even marginally higher (which, combined with the already-accepted 3 cp/square mobility gradient, it usually does when the engine stands better), converting a meaningful share of those draws to wins, while still allowing the engine to head into a repetition when it is worse (0.0 beats a negative eval). Concretely: in get_move, before the iterative-deepening loop, capture a module global _root_ply = len(board.move_stack). In _forced_draw(board), when len(board.move_stack) > _root_ply return True if board.is_repetition(2) (current position has occurred at least once earlier in the combined game+search move stack); when len(board.move_stack) <= _root_ply keep the existing board.is_repetition(3) check so the actual root is never instantly declared drawn and iterative deepening always yields a move even if the root already repeats earlier game history. Keep the halfmove_clock >= 100 and is_insufficient_material checks unchanged, and keep exactly one is_repetition call per node (is_repetition(2) subsumes the threefold case past the root), so node cost is unchanged. No new leaf term, no change to _model_evaluate, move ordering, quiescence capture logic, the transposition table, _budget_seconds or the deepening loop.
- Rationale: The dominant retained failure mode across four straight experiments is non-forced repetition draws from equal-or-better positions, and it is the largest single reservoir of recoverable points (34 draws in exp-0093, most non-forced). Four cheap flat positional leaf scalars have all failed to move it because they do not change the fact that the search cannot see the draw coming until the third occurrence. This mechanism attacks the failure at its actual cause — draw-detection timing in the search — and is standard engine practice (treat the first repetition in the tree as a draw). It is materially different from every exhausted mechanism: exp-0063 draw contempt changed the VALUE assigned to a known draw; exp-0068/exp-0082 changed the PERFORMANCE of the repetition probe (halfmove-clock TT bucketing, skipping impossible probes); neither changed WHEN a repetition is recognised as a draw, and no experiment in the 48-record window has. It is fully self-contained: about six lines in agent.py, one module global, no new coefficients, no weights change, no training pipeline, and it keeps the trained model entirely determinative of every non-drawn leaf.
- Guardrails: Scope: edit only agent.py; weights/ unchanged; no change to _model_evaluate, _ordered_moves, _quiescence capture/pruning, the TT key or size, _budget_seconds, or the iterative-deepening loop. NPS/leaf cost: the change replaces one board.is_repetition(3) call with one board.is_repetition(2) call (identical complexity) plus an O(1) len(move_stack) compare and a global read, so target node cost within ~1.03x; confirm search still reaches comparable depth in the arena.

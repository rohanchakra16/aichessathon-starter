- Title: Tablebase-free endgame mop-up king-drive term for converting won lone-king endgames
- Family: endgame-conversion-leaf-evaluation
- Hypothesis: In agent.py's _model_evaluate, after the existing piece loop, when the position is a clearly winning lone-king endgame, add a bounded coordinate-based mop-up term that gives alpha-beta a monotone gradient toward cornering the bare king and marching our own king up, converting a meaningful share of the ~30 non-forced threefold-repetition draws (many of them materially winning endgames) into wins without retraining. Concretely: (1) At module load, build a 64-entry tuple CENTER_DISTANCE giving each square's Chebyshev-or-Manhattan distance to the central 4x4 (standard mop-up 'center manhattan distance' table: values 6,5,4,3,3,4,5,6 by file added to the same by rank, range 0..6). (2) During the existing `for colour, sign` / `for piece_type` loop, cheaply accumulate, per side, the count of non-king pieces and a boolean 'has_mating_material' (>=1 queen or >=1 rook, or >=2 minor pieces, and 0 pawns on the weak side). (3) After the loop, gate: exactly one side (the 'strong' side) has mating material and the other side (the 'weak' side) has zero non-king pieces AND zero pawns (lone king only). If the gate is false, return unchanged. (4) If the gate is true, compute drive = 4.7 * CENTER_DISTANCE[weak_king_square] + 1.6 * (14 - chebyshev_or_manhattan_distance(strong_king_square, weak_king_square)), hard-cap drive at 60, and add `+drive` to score if the strong side is board.turn else `-drive`. Use only board.king(colour), chess.square_file/square_rank, and the piece counts already gathered. No change to _ordered_moves, _quiescence, _negamax, the transposition table, _forced_draw, _budget_seconds, the iterative-deepening loop, MATE handling, or weights/.
- Rationale: The dominant retained failure across six straight experiments is non-forced repetition draws, and the evidence shows a large, specific sub-population: endgames where the candidate has decisive or winning material but shuffles to a threefold draw because nothing in the evaluation rewards making progress once a forced mate is beyond the horizon (depth ~6-8 plus a 3-ply capture quiescence often cannot see mate in a KRvK-type ending). The accepted mobility term (exp-0089) rewards attacked squares, but a lone king already has near-zero mobility and driving it to the edge barely changes our attacked-square differential, so mobility supplies no cornering gradient. Mate-distance scoring (exp-0048/exp-0065/exp-0081, exhausted) only acts once a mate is found in-tree. Draw contempt (exp-0063, exhausted) changes the value assigned to a recognised draw but gives no directional signal toward the win. The mop-up evaluation is the textbook tablebase-free method for precisely this problem and has never appeared in the 48-experiment window, so it is materially new. It keeps the trained model fully determinative of every non-lone-king position (i.e. essentially all real play and all model-ablation openings); the term only perturbs positions the model was barely trained on and where the objectively correct move is close to tablebase play rather than model-subjective. It is self-contained: a ~15-line code change, one precomputed tuple, four fixed scalars, no coefficients from training, no weights change, no pipeline.
- Guardrails: Scope: edit only agent.py; weights/ untouched; no change to _ordered_moves, _quiescence, _negamax, the TT key or size, _forced_draw, _budget_seconds, or the iterative-deepening loop. NPS/leaf cost: the gate must piggyback on the existing _model_evaluate piece loop (accumulate the per-side non-king piece count and mating-material flag while it already iterates board.pieces); when the gate is false — virtually every middlegame and normal-endgame node, and every node in the model-ablation openings — the added cost is a handful of integer comparisons, so target node cost within 1.02x and confirm the arena reaches comparable search depth. When the gate is true the extra cost is ~2 board.king calls, 2 table lookups and a distance computation, which is negligible and rare. Model-move-ablation safety: the 3 s ablation openings start from standard opening positions and effectively never reach a bare-king endgame, so the term is inert on that path; require model_move_ablation to still show minimum_move_differences >= 8 and the strength gate >= 0.625 and confirm both are materially unchanged, not merely passing. Reliability/flag risk: no new work on the hot path, so re-verify the full stress_time_left_ms grid (1 / 25 / 100 / 1000 / 120000) with required_failures 0 and init under 50 s; exp-0094's worst single move was 0.80 s against the 2.25 s ceiling and 0.0004 s against 0.75 s at the 1 ms clock, and this change adds no measurable work, so that margin must be preserved. Correctness bounds: hard-cap the drive contribution (<= 60 model units, far below a minor piece and below any real mate score) so it can only break ties among equal-material king-shuffle positions and can never flip the sign of a position that material evaluation already calls winning or losing; never apply the term when the weak side still has a pawn (KPvK / KRPvKR can be fortress draws and the cornering logic is wrong there) or when material is equal; use only the documented python-chess API (board.king, board.pieces, chess.square_file, chess.square_rank) and never read library internals.

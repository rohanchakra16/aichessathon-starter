- Title: Rook on open / half-open file term in the leaf evaluation
- Family: leaf-evaluation
- Hypothesis: Add a cheap fixed rook file-status bonus to _model_evaluate. Before the `for colour, sign` loop (or once per call), fetch the two pawn bitboards as plain ints: white_pawns = board.pieces_mask(chess.PAWN, chess.WHITE) and black_pawns = board.pieces_mask(chess.PAWN, chess.BLACK). Inside the existing `for colour, sign` / `for piece_type` loop, when piece_type == chess.ROOK, set own_pawns/enemy_pawns from those two ints by colour and compute file_bb = chess.BB_FILES[chess.square_file(square)]. If file_bb & own_pawns == 0 and file_bb & enemy_pawns == 0, add sign * ROOK_OPEN_FILE (a fixed constant, ~18 cp). Else if file_bb & own_pawns == 0 (own side has no pawn on the file but the enemy does), add sign * ROOK_HALF_OPEN (~9 cp). Apply the bonus flat: no phase scaling, and no doubled-rook, rook-on-7th, rook-behind-passed-pawn, or connected-rooks sub-terms in this first version so the mechanism is tested cleanly. This gives alpha-beta a monotone reason to lift a rook onto the one open file and to create or preserve open files for its rooks, a progress signal that mobility (near-constant among quiet rook moves along a closed file) and the file-agnostic tapered PSQT do not express, directly targeting the passive-rook shuffling and passive-rook endgame losses seen across the exp-0091 repetition-draw and checkmate PGNs.
- Rationale: The dominant retained failure modes are non-forced repetition draws from equal-or-better positions with rooks shuffling on closed files, and lost simplified endgames where the rook never activates. exp-0091's passed-pawn term moved the arena from 0.508 to 0.531 but stayed inconclusive, and the previous audit's own guardrails explicitly pre-authorised rook-on-open-file as the next distinct positional term after an inconclusive passed-pawn arena, with bishop pair after that. Rook file activity is the canonical rook-endgame and middlegame progress heuristic, has never been tried in this project (absent from the experiment registry and from both exhausted-mechanism lists), and is fully self-contained: one documented-API bitboard AND per rook plus two hand-chosen constants, no move generation, no board.push, no new weights artifact, no training pipeline. It is preferred over bishop pair because it targets the largest combined loss-plus-draw column (passive-rook middlegames and rook endings) rather than a near-constant material scalar, and preferred over another king-safety term because exp-0090 already showed a static king-danger scalar does not move the needle.
- Guardrails: Keep the trained PSQT model and the accepted mobility term dominant: ROOK_OPEN_FILE must stay <= ~22 cp and ROOK_HALF_OPEN <= ~12 cp, so a realistic worst case (both rooks on fully open files) contributes under ~0.45 pawn, far below the model's ~118-170 cp margin RMSE, and no single-piece contribution approaches a minor piece. NPS / leaf-cost budget: fetch the two pawn bitboards once per _model_evaluate call as plain ints (board.pieces_mask); per-rook work is one chess.square_file call, one chess.BB_FILES index, and two int-AND truthiness tests, with no chess.popcount, no second legal-move generation, no board.push, and no per-leaf object allocation. exp-0091's stress showed the worst single move at the 120 s clock was 0.55 s against the 2.25 s ceiling and 0.04 s against 0.75 s at the 1 s clock, so keep the added leaf cost within roughly 1.2x. Use only documented python-chess API (chess.BB_FILES, chess.square_file, board.pieces_mask); never read library internals and never touch any path outside agent.py and weights/. No change to _budget_seconds, the iterative-deepening loop, move ordering, quiescence, or the transposition table. Must pass the full stress_time_left_ms grid (1 / 25 / 100 / 1000 / 120000) with required_failures 0 and init under 50 s, and must hold model-move-ablation minimum_strength_score >= 0.625 with >= 8 divergent moves at the 3 s ablation clock. If the paired arena is inconclusive, do NOT re-tune ROOK_OPEN_FILE / ROOK_HALF_OPEN, add phase scaling, or bolt on doubled-rook / rook-on-7th / rook-behind-passer / connected-rook sub-terms and call it a new experiment; move to the bishop-pair term, and if that is also inconclusive, flag an offline positional-feature retrain of weights/model.json (rook, king-shelter and pawn-structure features) for the human before declaring scientific saturation.
